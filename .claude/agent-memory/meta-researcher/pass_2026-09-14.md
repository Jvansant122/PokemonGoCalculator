**Recommended, pending meta-architect action:**

1. **New PreToolUse hook**: deny `Write` under `packages/engine/test/` unless the basename matches
   `*.test.ts` / `*.bench.ts` or the path is under `test/fixtures/`. Targets a real, twice-recorded
   incident: throwaway scratch scripts (`_scratch_bb_roster.ts`, `_scratch_bb_debug{,2,3}.ts`)
   landed in that tracked, globbed directory on 2026-09-13 instead of the session scratchpad,
   breaking lint/typecheck for concurrent agents — see
   `.claude/agent-memory/engine-developer/measurement_best_buddy_roster_mode_impact.md` ("Files"
   section) and `feature_best_buddy_roster_mode_2026_09_13.md` ("scratch-script-location
   incident"). Verified every one of the 44 real files currently under `packages/engine/test/`
   fits the allow-pattern (`Glob` run this session), so the rule has zero false positives against
   the current tree. Mechanics sourced from `code.claude.com/docs/en/hooks` (fetched 2026-09-14):
   `PreToolUse` fires before the tool executes and can block via exit code 2 (unconditional) or
   JSON `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny",
   "permissionDecisionReason":"..."}}` on stdout with a non-2 exit; `tool_input.file_path` is
   available for a `Write` call; matcher syntax matches a tool name directly (`"matcher": "Write"`).
   Cost: a hook is harness-level automation, not loaded into any agent's context — the only
   ongoing price is the script's own runtime (a string match, effectively free) each time `Write`
   fires. Write the path check as plain JS in the hook script (mirroring `post-edit.mjs`'s existing
   style) rather than relying on the doc-mentioned `if: "Write(glob)"` shorthand, which I did not
   independently verify beyond the one fetch.

2. **Sharpen `engine-developer.md`'s body**, not a new skill. Add the fodder-boss
   `timeToClearSeconds` quantization trap explicitly (a strong solo attacker 1-2-shots a 600 HP
   1-star boss, so clear time is quantized by discrete cast count and reads as nonsense —
   "pin against a never-clears boss, confirm `timeToClearSeconds === null` before trusting any
   delta") plus the scratch-script-location rule from #1, in the "Testing" section or a new short
   "Measurement tasks" subsection. This trap was recorded in engine-developer's own memory on
   2026-09-10 (`feature_swap_cost_bossmaxhp_friendship_bestbuddy_2026_09_10.md`, "floor-quantization
   test gotcha") and again 2026-09-11 (`feature_best_buddy_candidate_2026_09_11.md`), then still
   produced "absurd numbers" on 2026-09-13 (`measurement_best_buddy_roster_mode_impact.md`) despite
   living in a MEMORY.md index the agent's own charter says to read before starting — at 67 entries
   that index is flat and easy to skim past, so the fact needs to live in the body prose itself,
   not just be indexed. This directly follows this project's own precedent
   (`engine-verifier.md` gained an inline vitest-OOM paragraph 2026-09-12 rather than a new skill,
   specifically because a skill "costs a line in every session's listing and this fact is needed
   by exactly one agent" — same reasoning applies here). Cost: zero ongoing context — only loaded
   when `engine-developer` runs. Considered and rejected a brand-new "measure-before-building"
   skill for this precisely because the cheaper, already-adopted pattern fits better; said so
   rather than defaulting to a new skill.

3. **Extend the existing `post-edit.mjs` PostToolUse hook**, not a new one: add a fourth branch —
   when the edited file is `.claude/agents/*.md`, `.claude/skills/**/SKILL.md`, `CLAUDE.md`, or
   `HANDOFF.md`, run `npm run check-docs-drift` (already an allowed command per
   `.claude/settings.json`'s `Bash(npm run check-*)`). Right now editing any of those files
   triggers **zero** automatic check — the hook's three existing branches
   (`isEngineSrc`/`isWebSrc`/`isScenarioFile`) don't match `.claude/` paths at all, so a stale claim
   inside a skill or agent body (or CLAUDE.md/HANDOFF.md) only gets caught at `npm run verify` time
   if someone remembers to run it, or by a human reading it — which is exactly how the
   `add-scenario-assumption` skill's stale "the round-trip checker covers only six tabs" line was
   found (HANDOFF.md 2026-09-12: "went unnoticed until a human read it"). Note this specific stale
   line was PROSE ("It covers **all seven** tabs..." — I confirmed it now reads correctly), not the
   Step-0 table `check-docs-drift.mjs` already parses (that table-row check already existed and
   would have caught a table-row mismatch) — `check-docs-drift` still has no regex for a skill's
   own prose count-words the way it has one for CLAUDE.md's/agents' count-word claims (script
   internals, out of my remit to fix — flagging for whoever next touches `scripts/check-docs-drift.mjs`,
   most likely `data-sync` or the user directly, not a meta-researcher deliverable). Wiring the
   *existing* checker to *fire automatically* on `.claude/` edits is still a real, free win going
   forward for everything it already does check (table row counts, agent routing, command-name
   existence) — it currently gives every other file type a safety net and skips `.claude/` itself,
   which is backwards given `.claude/` is this project's second-most-edited surface this week.
   Cost: zero — same `PostToolUse`/`Edit|Write` matcher already in `settings.json`, only the
   `.mjs` script's internal branching grows by one `if`.
