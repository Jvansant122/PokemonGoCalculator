# Rule: never propose removing or de-scoping a tab

User instruction, verbatim, 2026-09-10:

> *"we dont care that the casual player doesnt want some tabs. any audit saying to remove an
> entire tab should be ignored"*

This tool targets the **high-investment player**. The deep tabs exist precisely because they
answer questions a casual player never asks. `casual-optimizer` rejecting four of six tabs on
premise is expected and correct output — it is **not** a defect, and it is not a backlog.

## How to apply

When any archetype's objection is to a tab **existing at all**:

- Label it `STRUCTURAL`.
- Give it **one line**.
- Move on.

Never write it up at length, never propose removing / merging / hiding / simplifying a tab on
its behalf, and never let it move a priority ordering.

## What is still in scope

Everything about how a tab **works**. A label nobody can parse, a number shown without its
caveat, a screen that buries the answer, a recommendation resting on a guess — all fully in
scope, from every archetype including `casual-optimizer`, which is often sharpest on these
precisely because it has the least patience for what the real users tolerate.

**Judge the execution. Leave the premise alone.**
